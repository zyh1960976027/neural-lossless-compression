# 项目文件与目录说明

项目 `neural-lossless-compression` 的使用方式与编码、解码示例见根目录 [README](../README.md)。本文件说明各类文件的职责、文档位置及命名约定。

## 目录职责

```text
neural-lossless-compression/
├── README.md                 唯一中文项目入口
├── AGENTS.md                 自动化协作工具读取的项目规范
├── run.py                    主线子词压缩、解压与往返校验入口
├── codec.py                  字节基线编码、解码和完整恢复验证入口
├── train.py                  字节模型训练入口
├── evaluate.py               字节模型概率评估入口
├── requirements-codec.txt    编解码附加依赖
├── neural_compression/       核心实现，包名与具体模型解耦
├── native/integer_range/     CPU 整数区间接口，复用 Constriction Rust 核心
├── scripts/                  实验、性能分析与环境脚本
│   └── conda/                环境激活与退出配置
├── tests/                    自动化检查
├── docs/
│   ├── 目录说明.md           文件职责与文档索引
│   ├── 使用指南/             环境、训练评估和文件编解码
│   ├── 实验方案/             实验运行方法与指标约定
│   ├── 实验报告/             已完成实验的记录与分析
│   ├── 实验数据/             纳入版本管理的精简 JSON 结果
│   └── 图片/                 文档图片
├── datasets/                 本地原始数据与预处理结果
├── checkpoints/              本地常用推理权重
└── experiments/
    ├── train/                字节模型训练记录及权重
    ├── test/                 评估、编解码与性能实验产物
    └── tokenizers/           子词词表、训练与编解码实验产物
```

最后三类数据目录由运行脚本生成或由使用者准备，完整内容不提交 Git。`.cache/`、`__pycache__/`、`.pytest_cache/`、`.conda-envs/` 等目录保存本地缓存或运行环境，不作为源码和报告目录。整理保留既有数据、权重及历史运行目录，避免改变实验记录中的路径和文件指纹。

## 核心实现职责

主线源码统一使用 `neural_compression` 包名，供入口脚本、实验脚本和自动化检查引用。包内的模型、分词、训练、概率量化与编解码模块分别承担对应职责，具体 Mamba-3 实现继续保留模型名称。

| 模块 | 职责 |
| --- | --- |
| `cli.py`、`__main__.py` | 主线命令参数、默认 BPE 4096 配置、路径检查、输出目录创建与编解码调度 |
| `model.py`、`config.py` | 模型结构、参数统计与训练配置 |
| `data.py`、`trainer.py`、`metrics.py` | 字节数据组织、训练恢复及概率指标 |
| `experiments.py` | 统一实验目录和默认权重位置 |
| `codec.py` | 字节编解码调度、文件格式识别、旧格式支持及恢复校验 |
| `codec_batched.py` | v3 格式的独立块区间编码 |
| `codec_batched_v4.py` | v4、v5 共用的批量共享区间编码与容器布局 |
| `codec_graph.py` | 复用推理缓冲区，并通过 CUDA Graph 记录和重放运算以减少调度开销 |
| `codec_step_adapter.py` | 为已安装的 Mamba 单步推理适配中间张量的存储布局 |
| `tokenization.py` | 字节可逆的 SentencePiece 分词与还原 |
| `token_codec.py` | 内嵌分词器的子词压缩容器与编解码 |
| `integer_range.py`、`native/integer_range/` | GPU 整数累计表与 CPU Constriction 批量整数接口 |
| `token_training.py` | 独立子词块训练、验证和早停恢复 |
| `token_experiment.py` | 子词实验参数、数据准备与文件指纹 |
| `token_pipeline.py` | 子词实验预检、训练选择、评测与报告生成 |
| `bpe_vocab_experiment.py` | BPE 词表规模实验、梯度累积配置、重复测速与历史比较 |

主线 BPE 通过 `run.py` 或 `python -m neural_compression` 运行，内部调用 `token_codec.py` 提供的子词编解码接口；默认权重和分词器位于 `checkpoints/bpe4096/`，调用示例见根目录 [README](../README.md)。根目录 `codec.py` 是字节基线命令行入口，包内同名模块承担具体实现。`codec_batched_v4.py` 同时用于 v4 和 v5；文件名保留兼容性来源，其职责不只覆盖旧格式。

## 辅助脚本选择

以下路径均相对于 `scripts/`。主线 BPE 文件编解码使用根目录 `run.py`，字节基线使用根目录 `codec.py`；实验、构建和环境维护按下表选择脚本。

| 脚本 | 用途 |
| --- | --- |
| `benchmark_codec_batched.py` | 对指定大小、批大小的字节样本进行独立进程编解码与校验，默认 v5 |
| `benchmark_enwik9_full.py` | 双模型预检及完整 enwik9 实验 |
| `benchmark_sentencepiece.py` | 字节、BPE 和 Unigram 三组实验的统一入口 |
| `benchmark_bpe_vocab.py` | 仅运行 8192、16384 两组 BPE 词表实验，复用 4096 历史结果 |
| `benchmark_byte_performance.py` | 字节路径优化前后的重复配对测速 |
| `profile_token_codec.py` | 子词编解码分阶段分析和重复对照测速 |
| `benchmark_probability_transfer.py` | 三个 BPE 词表的 FP32/FP16/GPU 整数传输对照、无损验证与重复测速 |
| `build_integer_range.py` | 构建 Constriction 0.4.2 的 CPU 整数区间接口 |
| `benchmark_codec_inference.py` | 比较 v4、缓冲区复用及 v5 图重放 |
| `watch_enwik9_completion.py` | 等待双模型实验完成，并独立复核最终文件与指标 |
| `profile_codec_batched.py` | 对 v3 字节编解码进行细分耗时分析 |
| `benchmark_codec_sizes.py` | 分析容器、概率量化及区间编码开销 |
| `benchmark_codec_v2.py` | 对照早期容器与 v2 紧凑共享编码流 |
| `install_conda_hooks.sh` | 将项目激活配置安装到既有 Conda 环境 |
| `activate.sh` | 通过脚本激活环境的兼容入口 |
| `conda/activate.sh`、`conda/deactivate.sh` | 环境激活时设置配置、退出时恢复配置 |

早期格式和性能分析脚本保留用于复现实验。普通文件编解码的当前默认方式以根目录入口和使用指南为准。

## 命名与产物约定

`README.md` 保留仓库通用入口名，使用中文正文，统一说明项目用途、主线运行方式和文档导航。其他中文 Markdown 文档采用能说明用途的中文文件名，按内容放入对应分类，不再新增 `report.md`、`results.md` 等英文命名的中文正文。`AGENTS.md` 是工具约定的配置文件名，保留供自动化工具识别。

Python、Shell、依赖文件和机器读取的 JSON、CSV 保留稳定的英文名称。新生成的中文实验汇总统一命名为 `实验报告.md`，与同一次运行的 `results.json`、`summary.csv` 放在一起。历史忽略目录中的报告原件保持原样，完成检查脚本同时识别新名称和旧名称。

新增实验使用独立运行目录，不把临时日志、权重、码流或缓存放入 `docs/`。只有需要随代码保存的精简结果进入 `docs/实验数据/`，对应的结论与分析进入 `docs/实验报告/`。

## 项目名称与迁移

仓库名为 `neural-lossless-compression`，核心包名为 `neural_compression`，项目入口为中文 `README.md`。名称描述无损压缩任务，模型配置、训练权重和压缩格式继续保留各自的具体标识。

本次将原中文项目说明合并到 README，并把主线的 `mamba3_byte_compress/` 包迁移为 `neural_compression/`；源码导入、测试、构建目标和当前使用文档同步更新。根目录工作区、已有 Conda 环境、历史数据和权重的存放位置保持原路径。实验报告中的源码链接指向当前实现，历史结果中的绝对路径、提交编号与指纹作为实验记录保留；新版本实验使用新的输出目录。

五个方案分支的职责与历史标签见[版本管理与协作](使用指南/版本管理与协作.md)。其余实验分支保留各自历史源码布局，使用对应分支的文档与接口。
