# 本周实验周报：SentencePiece BPE 与 Unigram 分词算法实验

## 一、实验目的与动机

本周在两层、无 MTP（多 token 预测辅助目标）的 Mamba-3 无损压缩系统中，引入 SentencePiece BPE 和 Unigram 两种子词表示，与原有字节表示进行对照。实验的核心问题是：将预测单位从单个字节改为可变长度子词后，能否改善实际压缩效果，以及这种改变对完整编码、解码速度和模型存储成本有什么影响。

字节模型每次从 256 个取值中预测下一个字节，表示直接、输出类别少，但需要处理较长序列。子词模型可以把常见字符串组合成一个 token，使同样大小的 token 窗口覆盖更多原始内容；与此同时，词表扩大到 4096，会增加输入嵌入、输出预测和概率处理的成本。因此，token 数减少并不必然意味着系统更快，分词算法的效果需要通过实际码流大小和端到端耗时共同评价。

本次工作不仅比较预测损失，还完成了可逆分词适配、4096 类概率与区间编码预检、GPU 训练配置选择、收敛控制及完整文件评测。最终目标是在逐字节无损还原的前提下，得到字节、BPE、Unigram 三套系统的实际 BPB、编码速度和解码速度，并区分神经权重共享与随文件分发两种使用方式。

## 二、SentencePiece BPE 与 Unigram 算法介绍

### 2.1 SentencePiece 与 BPE

SentencePiece 是直接从原始文本学习子词词表并完成分词、还原的工具，不要求先按空格完成词级切分。它将空白纳入表示，因此适合需要保留文本结构的任务。不过，默认文本规范化与任意原始字节的无损恢复并不等价，本实验另行关闭规范化并实现字节保真适配。相关设计见 [SentencePiece 原始论文](https://aclanthology.org/D18-2012/)及[官方说明](https://github.com/google/sentencepiece/tree/v0.2.1)。

BPE（Byte Pair Encoding，字节对编码）用于子词学习时，从较小的字符符号出发，统计相邻符号对的出现频率，每次合并当前最频繁的组合，直到达到目标词表规模。分词时按照学习到的合并优先级组合输入，常见字符串可以形成较长子词，罕见字符串则保留为较小片段。它的核心是基于频率的贪心合并，机制直观，固定模型后可以确定性地分词。名称中的“Byte”并不意味着本实验的 SentencePiece BPE 就是原来的 256 类字节模型；本实验使用子词词表，并额外启用字节回退处理词表覆盖之外的内容。参见 [BPE 子词方法论文](https://aclanthology.org/P16-1162/)。

### 2.2 Unigram

Unigram 将分词视为概率选择问题：为每个候选子词赋予概率，并用一条切分路径中各子词概率的乘积评价该路径。训练通常从较大的候选词表出发，通过 EM（期望最大化，即交替估计潜在切分与模型参数）优化概率，再按删除词条对语料似然的影响逐步裁剪词表。分词时通过动态规划寻找概率最高的切分路径，而非沿用一串局部合并操作。该模型也支持采样多种切分，但本实验关闭随机采样，使用固定分词结果。参见 [Unigram 原始论文](https://aclanthology.org/P18-1007/)。

这里的“一元独立概率”只用于分词器选择切分，并不意味着后续压缩模型忽略上下文。实际熵编码使用的是 Mamba-3 根据块内历史 token 预测的条件概率，两个模型承担不同作用。

### 2.3 两种算法的联系与区别

两者都通过有限子词词表处理常见与罕见字符串，可以在词表规模和序列长度之间折中。BPE 主要通过高频合并构造词表；Unigram 主要通过概率估计与候选裁剪构造词表，并对完整切分路径评分。本实验固定相同的 4096 词表规模、训练语料、神经骨干和编解码协议，以观察不同切分结果对实际系统的影响。分词器训练目标本身并不是最终神经压缩系统的 BPB，因此不能仅凭算法形式判断哪一种压缩效果更好。

## 三、实验设置

### 3.1 数据集与无损预处理

实验使用 enwik9，即英文 Wikipedia 2006 年转储中的前 1,000,000,000 字节，保留原始 XML、标记、空白和换行，不做正文抽取或清洗。数据来源说明见 [Large Text Compression Benchmark 数据页面](https://mattmahoney.net/dc/textdata.html)。本实验中 MB、GB 均使用十进制单位。

| 用途 | 原始字节区间，左闭右开 | 大小 |
| --- | --- | ---: |
| 训练 | [0, 100,000,000) | 100 MB |
| 验证 | [100,000,000, 110,000,000) | 10 MB |
| 独立测试 | [110,000,000, 1,000,000,000) | 890 MB |

两种分词器只从训练部分学习；验证集用于模型选择、线程配置和训练 batch 调优。测试集不参与词表学习与配置选择，训练前仅用于检查可逆性。完整 1 GB 额外评测用于与历史实验比较，由于包含训练、验证内容，不作为独立泛化结论的依据。

SentencePiece 固定为 0.2.1，词表总大小为 4096，包含字节回退项和必要特殊项；字符覆盖率设为 0.9995，关闭规范化、额外前缀、空白删除和随机分词，不添加句首、句尾及填充特殊 token。文本保留换行逐行处理，长行按 UTF-8 边界拆成不超过 64 KiB 的片段。针对原文中的“▁”、无效 UTF-8 字节及不完整字符，实现显式字节回退；解码直接拼接词条对应的字节，避免 token 跨块时损失字符。

两种算法均在完整 1 GB 上完成“原始字节→token→字节”的逐段比较和 SHA256 校验，另外覆盖连续空白、全部 256 个字节取值、无效 UTF-8、截断边界及跨块还原。验证集上比较 1、2、4、8、12、24 个分词线程，并核对不同线程数生成的 token 一致；最终 BPE 使用 24 个分词线程，Unigram 使用 12 个。词表学习阶段两组均使用 24 个线程。训练 token 提前缓存，正式编码则重新读取原文并分词。

### 3.2 系统架构与编解码方式

模型先输出 256 类或 4096 类符号的预测分数，再转换为概率分布，并由 Constriction Range Coding（根据预测概率进行无损压缩的区间编码方法）将概率量化为整数频率，对实际符号编码。解码端使用相同权重、分词器、环境和已经恢复的历史符号，复现相同概率并逐步还原输入。

三组均采用两层 Mamba-3 SISO 骨干，不使用 MTP；隐藏维度为 352，状态维度为 128，扩展倍数为 2，head dimension 为 64，分组数为 1，旋转位置编码比例为 0.5，前馈隐藏维度为 736，内部计算分块长度为 64，dropout 为 0。输入嵌入与输出层不共享权重。内部计算分块长度与实验的 2048-token 独立编解码块是不同配置。

| 配置 | 字节组 | BPE 组 | Unigram 组 |
| --- | ---: | ---: | ---: |
| 符号类别数 | 256 | 4096 | 4096 |
| 骨干参数量 | 3,275,212 | 3,275,212 | 3,275,212 |
| 总参数量 | 3,455,436 | 6,158,796 | 6,158,796 |
| 权重来源 | 历史 best-3M.pt | 从头训练 | 从头训练 |
| 编解码独立块大小 | 2048 字节 | 2048 token | 2048 token |
| 正式编解码 batch size | 1024 | 1024 | 1024 |

每个独立块开始时重置 Mamba 循环状态；块内首 token 使用均匀分布编码，其余位置根据已知前缀预测。批量推理同时处理最多 1024 个独立块，块内仍逐位置递推，尾批按实际块数处理。2048 表示状态重置周期，并非跨块滑动窗口。

字节组保留原有 v5 压缩格式。子词组使用内嵌分词器的独立容器，记录原始长度、token 总数、分块配置、权重及运行环境指纹，并使用 CRC 和 SHA256 检测损坏和还原错误。神经权重外部共享，另导出仅含推理权重与必要配置的独立包，用于计算含权重 BPB。

### 3.3 训练样本、超参数与停止规则

子词训练语料先分词为连续 token 流，再划分为不重叠的 2048-token 块，每轮打乱块顺序。一个完整块只训练块内 2047 个条件预测位置，不预测下一块的首 token；尾块填充位置不参与损失。每轮对完整验证集计算 BPB，加入各块首 token 的均匀编码成本，再按原始字节数归一化，使训练和编解码的状态重置边界一致。

| 超参数 | 两组子词模型的共同设置 |
| --- | --- |
| 优化器 | Adam，β₁=0.9，β₂=0.99，ε=10⁻⁸，weight decay=0 |
| 随机种子 | 2026 |
| 精度 | BF16 混合精度，主权重为 FP32 |
| 训练 batch size | 72，不使用梯度累积 |
| 数据加载 | 使用预先缓存的 token，额外加载进程数为 0 |
| 学习率 | 首轮线性预热到 0.0006，最低允许值为 0.000006 |
| 梯度裁剪 | 最大范数 5.0 |
| 验证频率 | 每轮完整验证一次 |
| 降学习率与早停 | 累计改善不足 0.001 BPB 时计数，每 5 轮学习率减半，连续 15 轮停止 |
| 权重选择 | 每次验证新低均保存，最终使用最佳权重 |

改善阈值相对于上次累计改善达到 0.001 BPB 的参考值计算，小幅改善允许累积；不足阈值的新低会更新最佳权重，但不立即重置早停计数。12 小时仅作为进度检查点，不是训练时限；每轮及每 15 分钟保存模型、优化器、抽样位置和训练控制状态。

训练 batch 通过真实前向、反向、优化器更新及验证计算测速确定。batch 72 的两组吞吐均约为 56.6 万个条件预测 token/s，显存保留峰值约 19.4 GiB；batch 80 和 128 因显存不足被淘汰。比较 0、2、4 个加载进程后选择 0。正式训练时 GPU 利用率采样约 99%，显存占用约 21.6 GiB。上述采样值不代表全过程平均值。

字节模型本次不重新训练。历史权重的“48000”指最佳检查点所在的参数更新步数，其训练 batch 为 32；不能与本实验完整遍历训练集的轮数直接比较。因此，字节对照属于历史模型复用，三组训练策略和总参数量并非完全一致。

### 3.4 环境、正确性预检与复现记录

实验环境为 Ubuntu 22.04.5 LTS、Intel Core i9-12900K、RTX 3090 24 GiB，进程可使用 24 个逻辑 CPU。主要软件版本为 Python 3.10.16、PyTorch 2.9.1+cu126、CUDA 12.6、mamba_ssm 2.3.1、Triton 3.5.1、SentencePiece 0.2.1、Constriction 0.4.2、NumPy 2.2.6 和 Protobuf 6.33.6。完整运行环境及依赖指纹保存在实验 JSON 中。

正式训练前，先对 256/4096 类均匀、随机、尖峰和零概率分布测试量化与区间编码，再用具有非零输出头的预检模型，对 10 MB 验证集各进行三次独立进程编解码。两组均无损恢复，同组重复编码的压缩文件 SHA256 一致。预检还覆盖高编号 token、状态重置、尾块和尾批；正式模型训练在这些检查通过后启动。

代码在 `experiment/sentencepiece-tokenizers` 分支分阶段提交，本次实验核心实现固定于 `0cc33f8`；之后的提交补充文档，最终结果报告提交为 `5371acd`，各阶段实际 Git 提交号另存于运行记录。实验目录为 `experiments/tokenizers/enwik9_sp4096_20261019`；原始 enwik9 的 SHA256 为 `159b85351e5f76e60cbe32e04c677847a9ecba3adc79addab6f4c6c7aa3744bc`。分词器、数据切片、缓存及权重均有独立指纹，精确回放应使用已保存且指纹匹配的产物。

统一入口支持准备、预检、调优、训练恢复、评测和汇总。从头复现时使用新的实验目录：

```bash
source scripts/activate.sh
python -u scripts/benchmark_sentencepiece.py all \
  --run-dir experiments/tokenizers/enwik9_sp4096_reproduce
```

### 3.5 指标与计时口径

实际 BPB（Bits Per Byte，即每个原始字节对应的压缩比特数）按完整压缩文件计算：

\[
\mathrm{BPB}=\frac{8\times\text{压缩文件字节数}}{\text{原始文件字节数}}。
\]

该指标计入分词器、容器和编码开销；含神经权重 BPB 在分子中再加入独立推理包，分词器只计一次。编码、解码速度均为“原始字节数÷总秒数÷1000”，单位为十进制 KB/s。

编码计时覆盖原文读取、实际分词、模型推理、概率处理、区间编码、文件写入及内部检查；解码计时覆盖读取码流、预测、区间解码、还原字节、写文件及内部校验。模型加载和预热单独记录，编码侧分词器加载初始化在计时之外，完整解码后的外部逐字节比较也在计时之外。本次保留了编码端重复还原检查和重新读取原文计算 SHA256 的过程，未在中途改变测速口径。

## 四、实验结果与分析

### 4.1 分词规模与训练情况

| 指标 | BPE | Unigram |
| --- | ---: | ---: |
| 100 MB 训练集 token 数 | 35,716,345 | 36,624,455 |
| 890 MB 测试集 token 数 | 336,000,223 | 344,652,694 |
| 测试集平均原始字节/token | 2.649 | 2.582 |
| 实际训练轮数 | 98 | 76 |
| 参数更新次数 | 23,814 | 18,924 |
| 累计条件预测位置 | 3,498,492,690 | 2,782,099,396 |
| 训练耗时 | 106.76 分钟 | 84.52 分钟 |
| 最佳权重所在轮次 | 83 | 68 |
| 最佳验证 BPB | 1.337151 | 1.341474 |

相对逐字节表示，两组在测试集上的 token 数分别减少约 62.25% 和 61.27%。按全测试集平均长度估算，2048 个 BPE token 对应约 5425 字节，Unigram 对应约 5289 字节，均大于字节组的 2048 字节；这表示相同 token 窗口下覆盖的原始内容不同，实际单块长度仍随文本变化。

两组训练都经历了验证平台期及降低学习率后的观察，并满足预设早停条件。BPE 的第 83 轮最佳权重之后继续训练至第 98 轮；Unigram 的第 68 轮新低相对第 61 轮累计改善约 0.000853 BPB，未达到重置计数的阈值，最终在第 76 轮停止。结果支持“已按约定规则训练到验证稳定”，但不能证明更长训练完全没有收益。验证 BPB 是预测概率对应的理论成本估计，不含完整容器和分词器开销，不能直接作为最终压缩文件 BPB。

### 4.2 独立 890 MB 主测试

| 方案 | 实际 BPB ↓ | 含神经权重 BPB ↓ | 编码 KB/s ↑ | 解码 KB/s ↑ |
| --- | ---: | ---: | ---: | ---: |
| 字节 | 1.341889 | **1.466228** | **380.10** | **372.74** |
| BPE | **1.287572** | 1.509112 | 269.13 | 351.49 |
| Unigram | 1.289601 | 1.511141 | 273.61 | 372.60 |

神经权重外部共享时，BPE 与 Unigram 的压缩文件分别为 143,242,414 和 143,468,062 字节，相比字节组的 149,285,142 字节，分别缩小约 4.05% 和 3.90%。BPE 比 Unigram 小 225,648 字节，约为 0.157%，说明本配置下 BPE 略占优势，但两者差距远小于它们与字节基线的差距。

速度方面，BPE 与 Unigram 相对字节组的编码速度分别降低 29.19% 和 28.02%；解码速度分别降低 5.70% 和 0.04%。两种子词方案直接比较，Unigram 编码快约 1.67%，解码快约 6.01%。这反映了本次系统实现和测量条件下的表现，不应推广为两种算法在所有语料或实现上的固定速度排序。

| --- | ---: | ---: | ---: | ---: |
| 字节，本次 | 1.337071 | 1.447733 | 379.69 | 374.25 |
| BPE，本次 | 1.274248 | 1.471418 | 258.33 | 360.08 |
| Unigram，本次 | 1.276955 | 1.474125 | 276.11 | 375.19 |
| 字节，历史记录 | 1.337071 | 未记录 | 361.73 | 371.81 |

本次字节组的完整 1 GB 压缩大小与历史记录一致，说明扩展子词路径后保留了基线压缩行为。完整 1 GB 上 BPE 仍略优于 Unigram，但该范围包含训练数据，应作为补充结果理解。历史与本次速度存在差异，也表明吞吐会受到运行条件影响；本次三组正式全量测速各执行一次，没有重复实验的置信区间。

### 4.4 差异原因与系统开销

从表示结果看，BPE 在相同词表规模下得到更少的 token，同样 2048-token 窗口覆盖的原文略多，可能有利于减少预测步骤和利用较长范围的结构信息。这与其较低 BPB 相一致，但不是已被单独验证的因果关系：词条可预测性、分块边界、训练轨迹和模型参数也共同影响最终码长，分词最短并不必然压缩最好。

子词组没有随 token 数减少而获得更高编码速度，原因在于每一步的成本也发生了变化。输出类别从 256 扩大到 4096，增加了输出层计算、概率传输、概率有效性检查和整数频率量化的处理量；此外还增加了分词及编码侧还原检查。上述开销可由实现和预检记录确认，但正式全量评测没有逐项消融，因此不能给每项开销分配确定的贡献比例。Unigram 的 token 更多却解码更快，也说明速度不能仅按 token 总数推断；概率分布对区间编码的影响及运行波动等只能作为待验证解释。

计入神经权重后，结论发生变化。字节组独立推理包为 13,832,763 字节，子词组各为 24,646,331 字节；较大的嵌入和输出层增加约 10.81 MB 权重体积，超过当前测试文件约 5.82—6.04 MB 的压缩收益。因此，在本次 890 MB 或 1 GB 单文件同时携带权重的场景下，字节组总 BPB 更低；模型能够预部署或被多个文件共享时，子词表示的文件压缩收益才更直接体现。

针对编码检查开销，另对 10 MB 验证集进行了三次独立 CPU 计时：BPE 的重复还原及摘要计算约 0.371 秒，重新读取原文计算 SHA256 约 0.009 秒，相对其 35.05 秒完整编码时间约占 1.08%；Unigram 对应两项合计约 0.395 秒。由此估计，单独省去这些冗余步骤对 BPE 的提速约为 1.1%，但这不是关闭检查后的端到端实测结果。该检查未改变正式实验代码与结果，也不能解释子词编码相对字节组的全部速度差距。

### 4.5 本周结论与适用范围

本周已完成从原始字节、确定性分词、模型预测到实际区间编解码的完整链路，并对三组的验证集、独立测试及完整数据共九次还原全部通过逐字节比较和 SHA256 校验。在当前配置下，共享神经权重时，两种子词方案均改善了文件压缩率；BPE 压缩效果最好，Unigram 解码速度更接近字节基线；若把完整神经推理包计入单文件成本，字节组更有优势。

上述结论限定于 enwik9、4096 子词词表、当前模型和实现。字节组复用历史权重，子词组总参数更多；相同 token 窗口覆盖的原始字节范围不同；两组仅使用一个神经训练随机种子，正式测速未重复。这些因素决定了本实验是三套具体系统的比较，尚不足以把全部差异归因于分词算法本身。后续有价值的验证是同配置重训字节基线、重复测速，以及围绕大词表概率处理开展针对性优化。
