# BPE GPU 整数量化与传输优化实验报告

> 历史记录：本文保留当时的实现、命令和测量口径。复现须检出对应历史版本，源码及保留材料见[历史索引](../../使用指南/历史索引.md)。旧码流和恢复副本按清单清除，旧实验目录不能直接续跑。

本次将概率量化和累计区间计算移至 GPU，Range Coding（区间编码，一种利用预测概率进行无损压缩的方法）仍由 CPU 上的 Constriction 0.4.2 执行。编码端只下载实际 token 的两个整数；解码端下载完整整数累计表，CPU 据此查找 token 并更新解码状态。复用三个词表的现有权重与分词器，未重新训练。

18 次完整往返均通过内部校验和外部逐字节比较，同词表同模式的三次压缩文件摘要一致。三个词表均满足 BPB 相对增幅不超过 1%，且编码、解码各三次整数模式耗时均低于对应 FP32 三次耗时。新路径通过 `probability_transfer="gpu_int"` 显式启用，保留 FP32 默认与对照路径，根目录日常字节入口没有迁移。

## 数据与测量口径

enwik9 偏移 100,000,000 起的 10,000,000 字节，三个词表使用完全相同原文。批大小 1024、独立块 2048 token、分词线程 24、PyTorch CPU 线程 1。每个词表的 FP32 与 GPU 整数模式各三轮，编码、解码分别在独立进程执行，共 36 个进程；轮换词表顺序并交替两种模式的先后次序。各次编解码顺序执行，没有并行运行其他 GPU 测试或重负载 CPU 回归。

硬件为 NVIDIA GeForce RTX 3090（24 GB）与 Intel Core i9-12900K；PyTorch 2.9.1+cu126、CUDA 12.6、NumPy 2.2.6、Constriction 0.4.2。CPU 扩展通过锁定依赖的 Rust release 构建，使用 Constriction 原始区间编码核心，无独立重写的熵编码器。完整环境与源码快照保存在实验目录。

正式编码包含读取原文、实际分词、推理、GPU 整数量化、传输、CPU 熵编码、文件写出及内部原文恢复校验；解码包含相应完整恢复过程。模型与分词器加载、完整批和尾批预热单列；外部逐字节比较另计。未启用分阶段性能采集，未清空文件系统缓存。BPB 按完整压缩文件计算，包含内嵌分词器、容器和校验信息，不包含模型权重；速度为原始字节数除以耗时，单位为十进制 KB/s。

## 实际传输量与流程

编码端满批单步从 FP32 的 16／32／64 MiB 减为 8 KiB，分别减少 99.9512%、99.9756%、99.9878%。每行只传两个 32 位整数：区间起点与频率。编码所需的实际 token 已在 CPU，提前上传目标 token 后由 CUDA Graph 内的 GPU 运算提取区间。保留双缓冲与提前一步预测，缓冲复用前等待对应下载完成。

解码端仍逐 token 推理，下载每行 V+1 个 32 位整数构成的累计表；CPU 在累计表中二分查找符号并执行区间解码。因此解码下载量略大于原 FP32 概率表，每满批每步多 4 KiB。该路径省去 CPU 浮点概率量化，但未宣称解码传输字节数下降。

| 词表 | FP32 编码/解码载荷 bytes | 整数编码载荷 bytes | 整数解码载荷 bytes |
| ---: | ---: | ---: | ---: |
| 4096 | 59,261,730,816 | 28,936,392 | 59,276,199,012 |
| 8192 | 105,779,003,392 | 25,824,952 | 105,791,915,868 |
| 16384 | 192,642,547,712 | 23,515,936 | 192,654,305,680 |

计数来自实际提交下载的张量大小，包含固定批中的无效行；排除预热、输入和目标 token 上传、检查标志及其他传输，不是 PCIe 总线计数器。每个模式的三轮传输计数一致。没有开启阶段计时，因此不能把整体提速精确拆分为传输、量化或 CPU 查找各自的收益。

## 量化、格式与正确性

模型计算和 FP32 概率生成保持原样。GPU 用 FP64 前缀和计算累计概率，并按总频率 2²⁴ 量化：每个符号先保留 1，其余频率按累计概率分配，再通过相邻累计值相减得到频率。零概率、极小概率仍有非零整数频率。编码和解码共用相同量化代码，GPU 检查原始概率合法性与累计表严格递增；CPU 整数接口检查传入区间边界。

新增子词容器 v3，记录 `probability_transfer=gpu_int`、24 位频率精度和 `cdf-f64-leaky24-v1` 量化规则。解码从文件头自动选择路径，模式或规则不一致时拒绝执行。新码流允许与历史不同；本次 FP32 对照仍逐一核对历史压缩文件摘要。整数模式的理论负对数指标按实际整数频率计算，不再将未传回 CPU 的浮点概率当作诊断依据。

CPU 测试覆盖三个词表的均匀、尖峰、极小与零概率，整数接口与原 Constriction 均匀模型码流一致；容器测试覆盖空文件、单 token、完整块、尾块、尾批、重复编码、参数拒绝和异常清理。GPU 测试比较串行完整累计表、串行目标区间与预取区间，在三个词表的完整 2047 步中逐项一致，并验证重置、缓冲生命周期和传输计数。共享字节路径和 FP32／FP16 GPU 回归全部通过。日志及独立校验记录保存在实验目录。
