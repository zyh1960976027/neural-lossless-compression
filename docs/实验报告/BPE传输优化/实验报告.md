# BPE 概率传输优化实验报告

本次将 GPU→CPU 的概率表由 FP32 改为 FP16 传输，CPU 收到后恢复为 FP32，再交给原 Constriction 0.4.2 完成概率量化与区间编解码。模型计算、词表、分词器、权重和独立块大小不变。三个词表的概率表传输载荷均减少 50%，18 次独立进程往返全部逐字节无损。

是否满足默认启用条件：**不满足，默认保持 FP32，FP16 作为显式可选模式保留。** 判定同时要求 BPB 相对增幅不超过 1%，且每个词表的编码、解码各三次 FP16 耗时均低于对应 FP32 的三次耗时。该规则用于排除本次短测中的明显波动，不代表统计显著性检验。

## 数据、环境与测量口径

使用 enwik9 偏移 100,000,000 起的 10,000,000 字节，逐字节范围对应现有验证集；运行前核对原始 enwik9 切片、三个词表验证文件和任务输入摘要一致。复用 4096、8192、16384 的已训练推理包，未重新训练。批大小固定 1024，每块 2048 token，分词线程 24，PyTorch CPU 线程 1。

CPU 为 12th Gen Intel(R) Core(TM) i9-12900K，GPU 为 NVIDIA GeForce RTX 3090，PyTorch 2.9.1+cu126，CUDA 12.6。每个词表的 FP32、FP16 各重复三次，编码与解码分别启动独立进程，轮换词表并交替两种传输模式的执行顺序。首次 4096 基线运行期间另有一次约 20 秒的 CPU 回归检查，可能造成轻微主机争用；逐次数据保留，结论不只依据该次测量。

模型加载、分词器加载和预热单列；正式编码从原文实际分词开始，包含 GPU 转换、传输、CPU 恢复精度、概率量化、区间编码、文件写出及内部校验。解码包括对应完整恢复流程。编码后的压缩文件摘要与解码后的外部逐字节比较不计入正式耗时。未清空文件系统缓存，结果代表预热运行条件。未开启分阶段性能采集。

## BPB 与编解码速度

BPB 为完整压缩文件比特数除以原始字节数，包含内嵌分词器、容器及校验信息；不包含神经权重。速度单位为十进制 KB/s，使用三次耗时中位数计算。

| 词表 | 传输方式 | 实际 BPB | 压缩文件 bytes | 编码 KB/s | 解码 KB/s |
| ---: | --- | ---: | ---: | ---: | ---: |
| 4096 | FP32 | 1.3983496 | 1,747,937 | 646.86 | 422.38 |
| 4096 | FP16 | 1.3983840 | 1,747,980 | 730.38 | 412.33 |
| 8192 | FP32 | 1.4822088 | 1,852,761 | 520.92 | 297.46 |
| 8192 | FP16 | 1.4822368 | 1,852,796 | 430.15 | 281.70 |
| 16384 | FP32 | 1.6493008 | 2,061,626 | 348.17 | 191.58 |
| 16384 | FP16 | 1.6493352 | 2,061,669 | 232.64 | 169.75 |

相对同期 FP32 基线的变化如下，速度变化为正表示更快。

| 词表 | BPB 增幅 | 编码吞吐变化 | 解码吞吐变化 | 满足完整验收 |
| ---: | ---: | ---: | ---: | --- |
| 4096 | +0.00246% | +12.91% | -2.38% | 否 |
| 8192 | +0.00189% | -17.43% | -5.30% | 否 |
| 16384 | +0.00209% | -33.18% | -11.40% | 否 |

三次正式耗时中位数及范围：

| 词表 | 传输方式 | 编码秒数：中位数 [最小, 最大] | 解码秒数：中位数 [最小, 最大] |
| ---: | --- | ---: | ---: |
| 4096 | FP32 | 15.459 [15.455, 15.569] | 23.676 [23.675, 23.709] |
| 4096 | FP16 | 13.691 [13.633, 13.707] | 24.252 [24.049, 24.278] |
| 8192 | FP32 | 19.197 [19.061, 19.245] | 33.617 [33.556, 33.622] |
| 8192 | FP16 | 23.248 [23.234, 23.269] | 35.499 [35.481, 35.733] |
| 16384 | FP32 | 28.722 [28.678, 28.783] | 52.198 [52.051, 52.458] |
| 16384 | FP16 | 42.986 [42.975, 43.418] | 58.911 [58.667, 59.102] |

FP16 新容器头比 FP32 增加 35 字节；4096、16384 的熵编码主体各增加 8 字节，8192 主体大小不变。由此可见，本次 BPB 增幅主要来自容器标识，不能把整个增幅都归因于概率舍入。

## 传输量与结果解释

每一步仍传输当前批所有行对应的完整词表，FP16 每项占 2 字节，FP32 每项占 4 字节。满批单步载荷由 4096／8192／16384 词表的 16／32／64 MiB 减少为 8／16／32 MiB。下表是一次完整编码或解码的概率表载荷，三次重复及两个方向的阶段计数一致。

| 词表 | FP32 概率载荷 bytes | FP16 概率载荷 bytes | 减少比例 |
| ---: | ---: | ---: | ---: |
| 4096 | 59,261,730,816 | 29,630,865,408 | 50% |
| 8192 | 105,779,003,392 | 52,889,501,696 | 50% |
| 16384 | 192,642,547,712 | 96,321,273,856 | 50% |

这些计数来自实际提交复制的张量大小，包含固定批形状中的无效行，排除预热、输入 token、概率检查标志和其他传输；它们是概率表载荷，并非 PCIe 总线计数器。

传输减半并不等于编解码耗时减半。新路径增加 GPU 的 FP16 转换和 CPU 的 FP32 恢复，CPU 仍需处理完整词表。编码保留双缓冲，使下一步 GPU 工作与当前步 CPU 熵编码重叠；解码必须等概率到达并完成当前 token 的区间解码，才能开始下一步。因此两端收益可能不同。这里依据整体测速说明净效果，没有将耗时变化归因于未经测量的单独模块。

实现中 CPU 恢复采用 PyTorch 在预分配缓冲中的转换。开发预检曾使用 NumPy 转换，4096 的一次完整编码／解码分别约 73.114／85.428 秒；同机单线程 1024×4096 数组的转换小测约为 NumPy 9.10 毫秒、PyTorch 0.60 毫秒，转换后数值逐项一致。前者已替换，探索结果仅用于解释实现选择，不与正式三轮结果混合汇总。

## 无损性、接口与复现

全部 18 次往返通过内部 CRC、长度与 SHA256 检查，以及独立进程外部逐字节比较；汇总再次核对保存的恢复文件和压缩文件摘要。同一词表、同一传输精度的三次压缩文件摘要一致。FP32 压缩结果还与历史归档完全一致。FP16 和 FP32 的概率舍入不同，不要求二者码流一致。

FP16 舍入使部分实际 token 的浮点概率下溢为零，本次三个词表分别出现 2032、2920、4750 个这样的 token。Constriction 仍为候选分配可编码的非零整数频率，因此全部恢复正确；使用浮点概率计算的理论负对数指标在这种情况下记为 null，实际 BPB 始终按压缩文件计算。

FP16 使用子词容器 v2，记录传输精度；FP32 仍使用 v1。解码辅助入口从容器读取精度和批大小，错误精度会被拒绝。测试覆盖三个词表的均匀、尖峰、极小和零概率，空输入、单 token、完整块、尾块、尾批、重复运行和损坏文件。GPU 验证覆盖完整 2047 步、FP16 与 FP32 舍入关系、串行与预取逐值一致、提前退出和状态重置；共享字节与子词 GPU 回归全部通过。

CPU 全量测试 109 项：99 项通过、10 项依赖显式 GPU 开关而跳过；另有 2 项汇总验收测试通过。显式开启 GPU 后，传输测试 4 项、共享推理回归 7 项均通过。
