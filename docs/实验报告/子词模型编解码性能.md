# SentencePiece 编解码性能分析与优化

## 1. 测量范围与结论

在保持原有模型、分词器、2048-token 独立块、batch size 1024 及无损校验的条件下，优化了大词表概率处理和编码阶段的执行调度。优化后的压缩文件与原实验逐字节一致，编码和解码吞吐均提高。

本次使用 enwik9 的固定 10 MB 验证集，在 RTX 3090 上进行优化前后配对测量；没有重新测量 890 MB 与完整 1 GB，因此下面的速度不能直接替换[原实验主表](子词与字节压缩实验结果.md)。验证样本包含 BPE 3,616,801 个 token、Unigram 3,710,535 个 token，均覆盖完整批次、尾批和 2048-token 状态重置。

| 方案 | 编码优化前 KB/s | 编码优化后 KB/s | 编码吞吐提升 | 解码优化前 KB/s | 解码优化后 KB/s | 解码吞吐提升 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| BPE | 258.60 | 626.45 | 142.25% | 335.52 | 411.71 | 22.71% |
| Unigram | 274.78 | 632.47 | 130.17% | 355.74 | 434.92 | 22.26% |

表中为三次无分阶段计时干扰的端到端速度中位数，单位为十进制 KB/s。改善百分比表示吞吐提升，不是耗时下降百分比。三次实际耗时如下：

| 方案 | 路径 | 编码秒数，中位数 [最小, 最大] | 解码秒数，中位数 [最小, 最大] |
| --- | --- | ---: | ---: |
| BPE | 原实现 | 38.669 [38.181, 38.890] | 29.805 [29.331, 29.940] |
| BPE | 优化后 | 15.963 [15.945, 16.038] | 24.289 [24.243, 24.379] |
| Unigram | 原实现 | 36.393 [36.329, 36.440] | 28.110 [28.016, 28.332] |
| Unigram | 优化后 | 15.811 [15.625, 15.843] | 22.993 [22.872, 23.161] |

## 2. 性能瓶颈与模块耗时

先对优化前后的两条路径分别做一次分阶段测量，再关闭分阶段同步，运行上一节的三次测速。分阶段计时会改变执行开销，因此下表用于定位瓶颈，最终速度以第一节为准。单位均为秒。

### 编码

| 模块 | BPE 原实现 | BPE 优化后 | Unigram 原实现 | Unigram 优化后 |
| --- | ---: | ---: | ---: | ---: |
| 原文读取与分词 | 0.586 | 0.584 | 0.529 | 0.533 |
| 还原检查及摘要 | 0.419 | 0.418 | 0.433 | 0.423 |
| 预测与传输的主线程等待/调用 | 15.137 | 6.301 | 15.587 | 7.654 |
| 概率行选择 | 5.991 | 0.044 | 6.064 | 0.045 |
| CPU 概率检查 | 8.375 | 0.001 | 8.518 | 0.001 |
| 概率量化与区间编解码 | 8.291 | 8.561 | 7.324 | 7.577 |
| 其他处理 | 0.231 | 0.172 | 0.241 | 0.170 |
| 合计 | 39.031 | 16.082 | 38.697 | 16.404 |

原实现的概率行选择会复制完整有效概率矩阵，随后 CPU 又扫描矩阵，检查概率是否有限、非负且每行有正概率。两项合计约占编码时间的 37%；实际原文读取与分词仅约占 1.4%—1.5%。因此，主要瓶颈来自大词表概率的处理方式，而非 SentencePiece 分词本身。4096 类输出在 batch 1024 时，每步的 FP32 概率矩阵为 16 MiB，是 256 类字节输出的 16 倍；token 数减少不能直接抵消每步处理量增加。

### 解码

| 模块 | BPE 原实现 | BPE 优化后 | Unigram 原实现 | Unigram 优化后 |
| --- | ---: | ---: | ---: | ---: |
| 还原字节、写出及摘要 | 0.459 | 0.462 | 0.468 | 0.495 |
| 预测与传输的主线程等待/调用 | 15.184 | 14.923 | 15.171 | 15.348 |
| 概率行选择 | 5.398 | 0.020 | 5.641 | 0.018 |
| 概率量化与区间编解码 | 8.951 | 8.862 | 7.971 | 7.903 |
| 其他处理 | 0.026 | 0.021 | 0.027 | 0.021 |
| 合计 | 30.017 | 24.287 | 29.280 | 23.785 |

解码原实现同样存在概率矩阵复制，但没有编码侧那次显式 CPU 全矩阵检查；所以移除复制后，解码的收益小于编码。解码必须先恢复当前 token 才能预测下一步，编码则已知原文 token，能提前提交下一次预测。

优化后编码表中的“预测与传输”是主线程提交、等待预测结果的时间。GPU 的下一步预测和传输与 CPU 当前步的区间编码重叠，不能把 GPU 事件时间再加到表中总耗时。BPE 的 GPU 模型计算与概率检查约 9.580 秒、概率下载约 5.115 秒；Unigram 对应约 9.856 秒和 5.213 秒。CPU 概率检查接近零表示检查已移至 GPU，并非删除检查。概率量化与区间编解码由 Constriction 库一次调用完成，本次合并计时，没有把两者拆成未经验证的独立数据。

## 3. 已落实的代码优化

1. **避免复制概率矩阵。** 独立块除最后一块外都为满长，有效行始终是连续前缀。编码和解码直接使用该连续区域，不再逐步建立概率矩阵副本。分阶段测量中，编码的行选择从约 6 秒降到约 0.045 秒，解码从约 5.4—5.6 秒降到约 0.02 秒。
2. **保留概率检查，减少 CPU 扫描。** 实际 GPU 预测器在同一推理图内检查产生的概率，再将检查结果随概率传回。通用预测器仍有 CPU 检查，覆盖非有限值、负数和全零分布。没有改变概率精度、量化规则或模型数值计算。
3. **让编码预测与区间编码重叠。** 使用两套独立缓冲区，当前概率供 CPU 编码时，GPU 处理下一步已知输入。递归状态仍按原顺序更新；缓冲区复用前等待相应传输完成，异常退出时也等待在途工作结束。
4. **补充可复现的性能测量入口。** [测量脚本](../../scripts/profile_token_codec.py)支持分阶段分析和重复配对测速，记录输入、权重、分词器、实现指纹、Git 提交、模型加载与预热时间、显存峰值及每次无损证明。原路径保留为测量对照，日常子词编解码默认使用优化路径。

实现主要位于 [子词编解码模块](../../mamba3_byte_compress/token_codec.py)与[批量状态推理模块](../../mamba3_byte_compress/codec_graph.py)。权重、分词结果、首 token 均匀分布、容器格式、CRC、编码侧还原检查及原文 SHA256 检查均保留。

## 4. 无损性与兼容性验证

分阶段分析完成 4 次独立进程编解码，重复测速完成 12 次，共 16 次完整还原均通过外部逐字节比较和 SHA256 校验。每次编码还必须与原实验已经保存的验证集压缩文件 SHA256 完全一致，汇总时另行对压缩文件进行了逐字节比较，全部通过。因此，本次验证同时检查了无损还原和原有码流兼容性。

| 算法 | 验证集压缩文件字节数 | 实际 BPB，优化前后相同 | 压缩文件 SHA256 |
| --- | ---: | ---: | --- |
| BPE | 1,747,937 | 1.3983496 | `b3edae0035239e1d7f1f0a02f54ace07c2ac7b159ca4fd5ec80753d070d5efc6` |
| Unigram | 1,756,905 | 1.4055240 | `67441c61b7fe3dce6462ca805a9c93639ca6eb4ff64a71d82d7531e900fc00f5` |

10 MB 上的 BPB 包含内嵌分词器，不能直接与 890 MB 的 BPB 比较。两组文件大小、推理包和权重都未改变，本次优化不涉及压缩率与速度的交换。

CPU 测试共 93 项，85 项通过，8 项依赖 GPU 的测试跳过；另行运行的 3 项子词 GPU 测试全部通过。测试覆盖高编号 token、完整 2047 步递推、尾块和尾批、状态重置、优化前后交叉解码、概率逐值一致、提前退出后的缓冲区清理，以及非法概率被拒绝且不留下部分输出。

共享推理模块另行通过原字节模型的 4 项回归测试，其中 GPU 测试在 batch 1024 和 787 下分别执行完整 2047 步，核对推理图与直接执行的概率及状态一致，并检查状态重置和缓存形状切换。

## 5. 测速口径、复现与后续瓶颈

模型和分词器使用原实验固定产物。编码计时从读取原文开始，包含分词、预测、概率处理、区间编码、写文件、还原检查及原文摘要校验；解码包含读取码流、预测、区间解码、还原字节、写出及内部校验。神经网络训练和分词器训练均不计入编解码时间。模型加载、预热和编码前分词器初始化在计时之外；解码完成后的外部逐字节比较单独记录。与原实验相同，结果记录使用的压缩文件 SHA256 在编码计时结束后计算。

编码、解码分别在独立进程运行；每轮交替优化前后顺序。两组分别使用固定的 24/12 个分词线程，PyTorch CPU 线程为 1。三次测速中，单进程模型加载约 4.18—4.61 秒，预热约 2.49—2.72 秒；GPU 保留显存峰值为 BPE 1470 MiB、Unigram 1510 MiB，优化前后相同。这是推理显存，不能与训练显存直接比较。

重复读取没有清除操作系统文件缓存，因此结果代表预热后的当前运行条件；没有报告冷启动文件读取性能。依赖版本与原实验一致，详见[结果与校验 JSON](../实验数据/sentencepiece-performance.json)。固定实现提交为 `1ee105588fbb5df716d904f57457d500af353aa1`，分支为 `performance/sentencepiece-codec`。

```bash
source scripts/activate.sh
python -u scripts/profile_token_codec.py profile --repeats 1 \
  --output experiments/tokenizers/performance_reproduce_profile
python -u scripts/profile_token_codec.py benchmark --repeats 3 \
  --output experiments/tokenizers/performance_reproduce_comparison
```

重复实验应使用新输出目录，避免混用实现或配置变化前的记录。原始记录保留于[分阶段分析](../../experiments/tokenizers/performance_final_profile_20261020/summary.json)和[重复测速](../../experiments/tokenizers/performance_final_comparison_20261020/summary.json)，包括每个进程的加载、预热与显存信息。

优化后，剩余主要成本是 GPU 预测和完整概率矩阵传输，以及 CPU 概率量化与区间编解码。原文分词、还原和文件摘要占比较小，删除校验的收益有限。本次已消除可直接确认的复制与扫描开销；进一步减少概率传输或改变量化实现需要单独验证整数频率及码流一致性。890 MB/1 GB 的最终吞吐仍需后续全量复测，不能由 10 MB 结果直接宣称。
