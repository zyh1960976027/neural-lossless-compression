# BPE 词表规模对压缩效果与编解码速度的影响实验

本实验只新增 8192、16384 两组 BPE。4096 组使用已归档结果，不重新训练、分词或测速。主要考察实际 BPB（每个原始字节的压缩比特数，越低越好）、编码速度及解码速度，同时记录模型大小和显存成本。

## 固定设置

数据沿用同一份 enwik9：前 100 MB 为训练集，随后 10 MB 为验证集，最后 890 MB 为独立主测试；完整 1 GB 包含训练与验证数据，仅作补充。分词器只从训练部分学习，保留字节回退、原有空白与特殊字节处理，关闭文本规范化和随机分词。两组分别训练独立分词器，分词线程固定为 24。

神经模型均采用两层、隐藏宽度 352 的 Mamba-3 骨干，骨干参数量为 3,275,212。8192、16384 组仅扩大输入与输出层，总参数量分别为 9,042,380 和 14,809,548。仍按独立的 2048 个 token 分块，每块首 token 使用均匀分布，其余 2047 个位置学习块内条件预测。不同词表对应的原始字节上下文长度会随分词结果变化，报告记录 token 数及平均每个 token 对应的字节数。

每组使用种子 2026 从头训练一次，采用 Adam、BF16，首轮线性预热至学习率 0.0006，最低为 0.000006。每轮完整验证，累计改善达到 0.001 BPB 时重置平台计数；连续改善不足每 5 轮将学习率减半，15 轮早停。每个验证新低保存最佳权重。12 小时是进度检查点，不是训练时限。

有效训练批大小固定为 72 块。从 72 的正因子按降序探测微批大小，选择保留至少 1 GiB 显存余量的最大安全值。每个候选在独立进程执行真实训练更新和验证。一次有效批次中的各微批按全部有效预测位置总数归一化，梯度累积后只执行一次裁剪与参数更新；轮末不足 72 块时按实际有效位置计算。验证批大小使用选定微批大小，数据加载进程数为 0，PyTorch CPU 线程数为 1。

## 运行入口与顺序

使用项目已配置的 Conda 环境，在干净的 Git 工作区运行；环境依赖不主动升级。先运行自动化检查及两种新词表的真实 GPU 检查：

```bash
conda activate mamba3
python -m unittest discover -s tests -v
MAMBA_CODEC_GPU_TEST=1 python -m unittest discover -s tests -p test_bpe_vocab.py -v
```

完整流水线按准备、预检、训练批量探测、训练、评测顺序执行。每一阶段先运行 8192 组，再运行 16384 组；正式验证集重复测速交替两组顺序，以减轻运行时漂移。

```bash
python -u scripts/benchmark_bpe_vocab.py all \
  --run-dir experiments/tokenizers/bpe_vocab_scale_20261020 \
  --vocab-sizes 8192 16384
```

入口只允许词表 8192、16384，未提供其他算法选项。可在同一配置和代码版本下重复上述命令恢复，或把 `all` 替换为 `prepare`、`preflight`、`tune`、`train`、`evaluate`、`report` 运行指定阶段。修改实验配置或实现后应换用新目录。清单核对数据、代码、历史归档及分词器指纹；训练断点还核对有效批大小、微批大小、优化器、随机状态和早停设置。断点只在一次完整参数更新结束后保存，每轮及每 15 分钟保存，并响应 SIGINT/SIGTERM。

## 预检与正式评测

准备阶段检查任意字节、特殊空白、无效 UTF-8 和跨块还原，并验证完整 1 GB 的分词与还原逐字节一致。预检分别覆盖 8192、16384 类均匀、随机、尖峰及含零概率分布的区间编解码，再用非零输出头的预检模型对 10 MB 验证集各执行三次独立进程编解码。重复编码必须生成一致码流。预检模型尚未训练，其 BPB 不用于正式结论。

正式评测使用各组最佳验证权重的独立推理包、现有优化编解码路径和批大小 1024。先对每组 10 MB 验证集做一次分阶段分析，再关闭分阶段计时进行三次测速；顺序为 8192→16384、16384→8192、8192→16384。随后每组分别执行一次 890 MB 主测试和一次完整 1 GB 补充测试。显存不足或正确性检查失败时停止，不自动更改批大小或切换执行方式。

编码和解码分别在独立进程执行。编码从原始文件读取和实际分词开始，计入预测、概率处理、区间编码、文件写入及内部还原和摘要校验；解码计入读取码流、预测、区间解码、字节还原、写出及内部校验。模型加载、预热、外部逐字节比较单列，不混入正式编解码时间。每次解码均与原文逐字节比较并核对 SHA256。

实际 BPB 包含完整压缩文件与内嵌分词器；含权重 BPB 另外加入只包含推理所需权重和配置的推理包，不计优化器。速度按原始字节数计算，单位为十进制 KB/s。10 MB 报告三次耗时的中位数、最小值、最大值和原始样本；890 MB 与 1 GB 为单次测量。显存分别记录 PyTorch 已分配与预留峰值，不等同于整卡用量。

## 历史比较与结果文件

4096 的对照只读取已归档的[压缩实验结果](../实验数据/sentencepiece-results.json)和[优化后性能结果](../实验数据/sentencepiece-performance.json)。各数据范围分别比较实际 BPB；速度改善百分比仅针对相同 10 MB 数据、相同硬件和依赖版本的优化后历史结果计算。890 MB、1 GB 的旧实现速度仅列为历史参考，不能将实现优化收益归因于词表变化。4096 没有同期复测，每个新词表只有一个训练种子，报告明确保留这两项限制。

根目录下保存 `sweep_manifest.json`、`environment.json`、`status.json`、`results.json`、`summary.csv` 和 `实验报告.md`，环境记录包含 Conda 显式包清单、Python 包版本及 GPU/驱动信息。`v8192/`、`v16384/` 分别保存分词器、训练断点与曲线、预检记录、独立推理包和全部编解码产物。流水线使用文件锁避免同一目录并发运行，缺失结果在报告中标记为未完成，不使用估计值填充。

最终分别报告实际 BPB 的变化、编码吞吐变化和解码吞吐变化，并同时呈现权重成本、token 数和显存变化。两项速度都提高且压缩文件更小时，可报告三项指标同时改善；出现取舍时按实测结果说明，不预设大词表一定更好。
