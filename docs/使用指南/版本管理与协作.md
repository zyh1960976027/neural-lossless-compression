# 版本管理与协作

项目 `neural-lossless-compression` 长期维护五个方案分支，`main` 是 BPE 4096 主线，采用一维 Mamba-3 序列模型、GPU 概率整数量化及 CPU 区间编码。主线基准以[GPU 整数量化实验报告](../实验报告/BPEGPU整数量化/实验报告.md)为准。BPE 8192、16384 及 FP16 传输作为可复现的对照实现和历史报告保留，不另外占用长期分支。

## 分支及来源

| 分支 | 维护方案 | 整理时的来源 |
| --- | --- | --- |
| `main` | BPE 4096、GPU 整数量化、范围编码 | `experiment/bpe-vocab-scale` 的 `96de122`，加入最新 GPU 量化实现、报告及协作说明 |
| `experiment/unigram` | Unigram 4096 子词方案 | `bdd731c`，包含子词编解码预取和传输缓冲优化 |
| `baseline/byte` | 字节概率模型及 v5 编解码基线 | `bdd731c`，包含字节编码预取和配对性能验证 |
| `experiment/mtp` | 多 token 预测训练和编解码 | 原 `MTP` 分支的 `922f0cb` |
| `experiment/model-scale` | 模型深度和参数规模实验 | 原 `模型规模实验` 分支的 `6ba330d` |

Unigram 与字节基线从同一个已优化历史节点起步，分别补充分支入口说明，后续独立提交各自方案的改动。历史实现和脚本留在对应快照中，不为拆分支删除共享代码。各分支的依赖和入口以该分支文件为准，切换旧方案后不要套用主线的 BPE 权重。

查看分支和切换方案：

```bash
git branch
git switch main
git switch experiment/unigram
```

切换前先提交当前改动。训练和性能测量应记录提交编号、环境及权重和分词器摘要；正式实验使用独立运行目录。

## GitHub 建仓方案（待确认）

建议在项目所有者的个人 GitHub 账号下创建私有仓库 `neural-lossless-compression`，默认分支为 `main`。新建空仓库，不自动生成 README、许可证或 `.gitignore`，随后上传本地五个分支和上述标签，保留完整提交历史。仓库地址和所有者账号确认后再执行创建与上传。

主线以中文 `README.md` 为统一使用入口，核心 Python 包为 `neural_compression`。具体 Mamba-3 模型、环境名称及历史实验文件保留原有技术标识。其他实验分支保留各自快照的源码布局，协作时按对应分支的包名与文档运行；涉及主线的公共修复同步调整导入路径。

只上传源码、文档、精简实验结果及 Rust 依赖锁文件。数据集、模型权重、完整实验码流、恢复文件、运行环境及本机编译的共享库继续由 `.gitignore` 排除。协作者克隆仓库后按[运行环境](运行环境.md)准备依赖，并另外取得匹配的 BPE 4096 分词器与推理权重，在自己机器上重新编译整数区间接口。

创建完成后，由所有者在仓库设置中邀请指定的 GitHub 用户；收到邀请的人接受后参与开发。GitHub Free 支持在个人私有仓库中添加协作者，见[官方邀请说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository)。仓库公开性、许可证及协作者名单由所有者决定，本次本地整理不自动设置。

## 合作约定

五个方案分支分别接受对应方案的改动；跨方案的公共修复通过独立提交选择性同步，避免把实验专有行为直接合并到主线。每次提交说明问题、改动和验证结果，涉及编解码或概率量化时须验证原文逐字节恢复，并保留实验配置与代码版本。

建议协作者为每项改动建立临时任务分支，通过 Pull Request（合并请求）说明修改并请另一位成员审阅；完成后删除临时分支，长期维护分支仍固定为五个。合并主线前运行：

```bash
python -m unittest discover -s tests -v
```

真实 GPU 检查按相应指南和测试的环境要求显式开启。缺少 GPU 或没有执行相关测试时，在合并请求中写明。GPU 性能变更使用相同数据和配置重复测量，并与主线基准比较。主线要求评审的规则先作为协作约定执行，是否启用 GitHub 强制规则待确认账号套餐支持情况后再配置，相关限制见[官方分支保护说明](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches)。
